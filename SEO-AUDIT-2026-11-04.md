Status: improvements implemented **locally only**, awaiting publication approval. No commit, push, deployment, campaign setting, tracking code, consent code, booking destination, stylesheet or navigation change was made during this audit.

## Scope and evidence

Reviewed all 19 HTML documents, shared CSS/JavaScript, routing configuration, sitemap, robots, the generated service catalogue and structured data. There are 14 indexable canonical pages and five intentionally noindexed utility/campaign/redirect documents. Tested public production HTTP responses and local rendering. Browser checks covered all 14 canonical pages at 1280px desktop and 390 × 844 mobile widths. This is a technical/content review, not access to Search Console ranking data or a guarantee of indexing or rankings.

Verified business details: Lazoya; 37 Bis Avenue Jean Guiton, 17000 La Rochelle, France; +33 9 56 67 30 09. Capitalization of “bis” and abbreviation of “avenue” vary but identify the same address. Phone destinations consistently use +33956673009. No invented geo coordinates, profile URL, rating, certification, price or service was added.

## Full technical checklist

- **Titles and descriptions:** all 14 indexable pages have a unique nonempty title and description. Improved three pages without mechanically rewriting already relevant metadata. Local coiffure title is “Coiffure, coloration & balayage à La Rochelle | Lazoya”; épilation title specifies cire; massage description now names verified body areas, including hands and feet. Updated corresponding OG/Twitter descriptions and WebPage/Service descriptions consistently.
- **H1/H2:** exactly one H1 per canonical HTML document and one in the rendered DOM at both widths. Service catalogue categories use H2 and services H3. Existing local service headings are relevant; new coiffure H2 covers balayage. Preserved homepage H1/design and all catalogue labels, including Planity spelling.
- **Canonicals:** each of the 14 indexable pages self-canonicalizes to HTTPS www with trailing slash. Metadata agrees with sitemap. No duplicate indexable titles/descriptions found. Technical canonical correctness does not prove Google's selected canonical.
- **Redirects/404:** public HTTP checks passed for canonical routes, configured directory index aliases, trailing slashes, campaign query retention, and a genuine nonexistent-page 404. Domain exception: 307 non-www hop above. Some index.html aliases have an extra Vercel trailing-slash hop before their configured redirect; internal canonical links avoid those aliases. No need to change navigation for this.
- **Sitemap/robots:** robots permits crawling and points to the correct sitemap. The sitemap has the same 14 canonical URLs, no duplicate entries or noindexed utility routes. Updated lastmod only for the seven service pages edited in this task. Not submitted to Google.
- **Indexability:** no HTML noindex directives on important service pages. Production canonical responses are 200. No X-Robots-Tag was present on the homepage host probes; sitewide indexing still requires Search Console verification.
- **Internal linking:** every indexable page is reachable through HTML links from home. Prestations is the service hub. Added contextual links on three weaker landing pages. No new competing location/keyword pages.
- **Mobile:** all 14 pages render with one H1 and no document-level horizontal overflow at 390px and 1280px. Tested mobile menu → reservation page, a new maquillage → coiffure link, and the new FAQ disclosure. No console errors recorded during the local browser pass. This was not a complete device/browser matrix or a Lighthouse accessibility audit.
- **Images:** all img elements in the 19 HTML documents have alt attributes; empty alt on the decorative reservation avatar is appropriate because the enclosing link has an accessible name. Indexable-page images have width/height attributes. Gallery photos use 480/960 WebP srcsets, lazy loading and asynchronous decoding. Their labels describe the actual visible work; the exact treatment technique cannot always be inferred from a photograph. No speculative alt claims added.
- **Asset sizes:** shared styles.css about 61 KiB, seo-pages.css 6.6 KiB, app.js 87 KiB. Homepage HTML about 87 KiB; the sum of its image src file sizes is approximately 1.25 MiB, including below-fold/hidden-view content. This is a static source-size inventory, **not measured initial network transfer**. Largest homepage img source found is a 131 KiB product JPEG; large original PNG files remain on disk but many references already use optimized WebP copies. Stored originals alone are not evidence of a page-load cost. No extra carousel assets or images introduced.
- **Structured data:** homepage identifies BeautySalon and HairSalon, with postal address, telephone, opening hours, catalogue and reservation action. Service, WebPage, ItemList and BreadcrumbList entities exist as appropriate. JSON parses and identifiers/references resolve in the custom checker. Added a provider consistency check against homepage NAP for all seven Service entities. The new nested provider copies contain verified NAP details; opening hours remain on the homepage business entity. The owner confirmed Monday closure and explained that Planity’s different Monday hours are intentional testing, so the existing website hours and homepage schema remain correct and unchanged. No rating/review markup added. Google's Rich Results Test was not run.
- **Open Graph:** unique page titles/descriptions and canonical OG URLs already present, shared storefront image resolves, image type/dimensions/alt and Twitter metadata present. Three edited pages' sharing fields remain synchronized with their descriptions.
- **Broken links/duplication:** custom validation found no missing internal HTML links, fragments or referenced img/script/link files. Public HTTP smoke checks passed; outbound third-party sites were not exhaustively crawled. The catalogue is intentionally repeated between the all-services hub, category pages and Planity. That is useful product/service information; it does not justify pointing category canonicals at the hub. Added distinct editorial guidance rather than more duplicate keyword pages.
- **HTML availability:** essential landing descriptions, service names/prices/durations, booking links, FAQs and structured data are already in server-returned HTML. Native details disclosures do not require JavaScript to contain the text. Client-side home filters are supplementary because dedicated category pages have static catalogue HTML. Diagnostic is intentionally noindexed and is not an essential crawl route.
